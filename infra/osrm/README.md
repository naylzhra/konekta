# OSRM dengan data jalan Bandung

Compose dasar memakai `osrm-mock`; overlay OSRM memakai graf jalan Bandung yang sudah disiapkan di `infra/osrm/data/`. Tile OpenStreetMap pada mobile berbeda dari graf routing. Mock mengembalikan rute garis lurus dan `/nearest` mengembalikan titik asal tanpa penyesuaian jalan.

1. Ambil ekstrak **OSM PBF** yang mencakup seluruh area layanan dari [BBBike Extract](https://extract.bbbike.org/) (pilih area Bandung Raya dan format PBF), atau gunakan [ekstrak Java dari Geofabrik](https://download.geofabrik.de/asia/indonesia/java.html) lalu potong area yang dibutuhkan memakai [Osmium](https://docs.osmcode.org/osmium/latest/osmium-extract.html). Periksa bahwa semua titik di `ROUTES.md` berada di dalam area ekstrak.
   Untuk Geofabrik, jalankan `powershell -NoProfile -ExecutionPolicy Bypass -File infra/osrm/extract-java.ps1 -Bbox 'LEFT,BOTTOM,RIGHT,TOP' -SourcePbf 'infra/osrm/geofabrik/java-261020.osm.pbf'` dari root repo setelah menentukan batas area dalam urutan longitude,latitude. Skrip memotong PBF yang sudah tersedia dengan Osmium di Docker, memastikan 51 titik K1 tercakup, lalu menyimpan `bandung.osm.pbf`. Tanpa `-SourcePbf`, skrip mengunduh ekstrak Java terbaru. Batas area wajib diberikan agar cakupan tidak ditebak.
2. Simpan ekstrak sebagai `infra/osrm/data/bandung.osm.pbf`. Direktori `data` tidak masuk Git.
3. Dari PowerShell pada root repo, jalankan `./infra/osrm/prepare.ps1`. Skrip memakai image Docker resmi OSRM untuk menyiapkan graf mobil, pejalan kaki, dan motor dari PBF yang sama. Jika graf mobil sudah ada, jalankan `./infra/osrm/prepare.ps1 -Modes foot,motorcycle`.
4. Jalankan `docker compose -f infra/docker/docker-compose.yml -f infra/docker/docker-compose.osrm.yml up -d --build`. Overlay mengarahkan gateway, pooling, dan optimasi stop ke OSRM nyata serta mengizinkan persetujuan kandidat yang dihasilkan dari run baru. Graf mobil, kaki, dan motor tersedia pada port 5002, 5003, dan 5004. Compose dasar masih menyalakan kontainer mock.
5. Jalankan `docker compose -f infra/docker/docker-compose.yml -f infra/docker/docker-compose.osrm.yml exec gateway python -m app.cli.sync_k1_route` untuk mengganti garis lurus antarstop dengan lintasan jalan hasil OSRM. Jalankan ulang perintah ini setelah peta OSRM diperbarui.
6. Uji `http://localhost:5002/nearest/v1/driving/107.64085963908062,-6.945891140531955?number=1` dan `http://localhost:5002/route/v1/driving/107.64085963908062,-6.945891140531955;107.60567416923172,-6.918301385527375?overview=false`. Gunakan port 5003 dengan profil `foot` untuk jalan kaki dan port 5004 dengan profil `motorcycle` untuk motor. Respons harus `code: Ok` dan `/nearest` harus mengembalikan waypoint jalan. `GET http://localhost:8000/corridors/K1/path` mengembalikan lintasan untuk garis rute pada peta mobile.

Graf OSRM dibuat dari data jalan OpenStreetMap, bukan dari daftar 51 stop. Daftar stop tetap menjadi geometri koridor K1 dan lokasi naik/turun yang diberikan pengguna. OSRM membantu snapping serta estimasi waktu tempuh; kecocokan titik dengan keselamatan dan aturan berhenti tetap perlu ditinjau oleh government.

Pada database yang sudah memiliki volume Postgres, file migrasi baru tidak diterapkan ulang secara otomatis oleh `docker-entrypoint-initdb.d`. Terapkan `009_feeder_1_route.sql`, `010_virtual_stops.sql`, lalu `011_k1_active_stops.sql` secara berurutan, atau buat database pengembangan baru.
