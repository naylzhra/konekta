# forecasting-service

XGBoost forecast of hourly feeder demand per kecamatan (Kota Bandung),
7 days ahead. Runs as two one-off jobs rather than a long-lived API:

| Job | Command | Writes |
|---|---|---|
| Train | `python -m app.training.train` | `artifacts/model.json`, `artifacts/meta.json` |
| Predict | `python -m app.jobs.predict` | `demand_forecasts` table (Postgres) |

The gateway serves the forecasts to the dashboard at
`GET /dashboard/demand-forecast?days=7` (government/admin only).
`artifacts/` is a Docker volume (`forecasting_artifacts`), not committed.

## Data

There is no historical feeder-demand data for Bandung — the service doesn't
exist yet — so the model is trained on:

1. **Synthetic data** (`data/synthetic_demand.csv`, 2 weeks, ≈530 trips/day),
   generated by `python -m app.training.synthetic` with a fixed seed.
   Volume is calibrated on Trans Metro Bandung ridership (873,572
   passengers in 2019, Open Data Bandung) × an assumed 25% feeder share;
   the split across kecamatan and the weekend factors are assumptions
   (`app/data/kecamatan.py`). Synthetic rows are down-weighted
   (`SYNTHETIC_WEIGHT`, default 0.3).
2. **Trial data**: `trip_plans` from the KONEKTA app, counted per kecamatan
   (by origin, `kecamatan` table from migration 014) per local hour.
   Picked up automatically on every retrain.

Forecasts are therefore not representative of real feeder demand until
enough trial data has been collected; retrain after each trial period.

## Features & evaluation

Calendar features (hour, day of week, weekend) + kecamatan and target
encodings (mean demand per kecamatan, per kecamatan × hour, per kecamatan ×
day type), objective `count:poisson`. Training holds out the last 3 days
and prints MAE against a seasonal-mean baseline; the numbers are stored in
`meta.json` under `metrics`.

## Running locally

With the stack from `infra/docker/docker-compose.yml` up (migration 014
applied):

```bash
docker compose -f infra/docker/docker-compose.yml run --rm forecasting-service python -m app.training.train
docker compose -f infra/docker/docker-compose.yml run --rm forecasting-service python -m app.jobs.predict
```

Synthetic-only training without Docker/Postgres:

```bash
cd services/forecasting-service
pip install -r requirements.txt
python -m app.training.train --no-db --output /tmp/artifacts
```
